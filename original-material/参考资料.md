## 任务 A：Proxy 

任务 A 的目标是实现：

```text
客户端请求
→ Proxy 创建或选择 Session
→ 启动或选择 Cirrus
→ 启动 UE，并传入 Cirrus 地址
→ 等待 UE Streamer 就绪
→ 将客户端路由到 Cirrus
→ Cirrus 完成 WebRTC 信令
→ UE 与浏览器直接传输媒体流
```

## 任务 B：渲染—编码解耦

任务 B 当前阶段只实现以下最小闭环：

```text
UE 渲染结果（GPU 显存）
→ 异步 GPU Readback
→ DRAM 固定帧队列
→ 上传到编码器输入 Surface（GPU 显存）
→ 复用 UE 原生 AVEncoder/NVENC
→ H.264 返回 Pixel Streaming
→ WebRTC 发送客户端
```

需要注意：普通 DRAM 是阶段一用于验证接口边界的中间存储。NVENC 通常消费 GPU 侧输入 Surface，因此 DRAM 帧还需要上传到编码 GPU 的输入 Surface，并不是让 NVENC 直接编码普通 DRAM。

### 参考资料

[UE FRHIGPUTextureReadback API](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/RHI/FRHIGPUTextureReadback)：理解 `EnqueueCopy()`、`IsReady()`、`Lock()` 和 `Unlock()` 的作用。在线页面可能对应较新的 UE 版本，函数和行为最终以本机 UE 4.27 源码为准。

[NVIDIA CUDA Programming Guide：Page-Locked Host Memory](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/understanding-memory.html)：只阅读 Page-Locked/Pinned Host Memory 部分，理解普通内存与 Pinned Memory 的区别，以及异步 Host↔GPU Copy 为什么需要 Pinned Memory。

[NVIDIA NVENC Video Encoder API Programming Guide](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/nvenc-video-encoder-api-prog-guide/index.html)：重点阅读 Basic Encoding Flow、Encoder Input Buffer、Resource Registration、Map/Unmap Input Resource、Encode Picture 和 Bitstream Output。阅读目的是理解 UE 原生编码器需要什么输入，不是从头实现 NVENC。

[NVIDIA Video Codec SDK Samples](https://github.com/NVIDIA/video-sdk-samples)：了解 NVIDIA 官方编码示例的目录结构和可复用封装。

[NVIDIA AppEncCuda 示例](https://github.com/NVIDIA/video-sdk-samples/blob/master/Samples/AppEncode/AppEncCuda/AppEncCuda.cpp)：重点查看“读取 Host Frame → 获取 Encoder Input Frame → CopyToDeviceFrame → EncodeFrame → 获得编码 Packet”的流程。该示例用于理解 DRAM 消费端，实际工程仍复用 UE 的 AVEncoder/NVENC。

[NVIDIA Nsight Systems User Guide](https://docs.nvidia.com/nsight-systems/UserGuide/index.html)：学习查看 CUDA API、Device-to-Host/Host-to-Device Copy、CUDA Context、Stream 和 CPU 等待时间。当前只需掌握时间线分析，不要求学习 Nsight Compute。
